## 8. 用户反馈修正（K线"一排长竖线" / 顶部挤在一起）

### 8.1 K线变成"长长的一根线"——新浪解析 low 起始位置错位
- `kline_parse_sina()` 老代码用固定偏移：open/high +8、close +9、volume +10 都对，
  但 **low 只有 3 个字母**，值在 `l+7`，写成 `l+8` 会读到 `".930"` → `atof` = 0.93（本该 8.93）。
- 后果：每根K线的 low ≈ 0.9 而 high ≈ 9，影线从顶拉到画布底 → **50 根全高度竖线**，
  蜡烛实体被压成顶部 2px 的小点。用户看到的就是"一排长长的线"。
- 修法：新增 `sina_num(key)` —— 找到 `:` 后跳过引号和空格再 atof，
  兼容 `"low":"8.930"` 与 `"low": "8.930"` 两种返回；key 用 `"low"`（不带冒号）匹配。
  另外加了两道保险：字段顺序必须 open<high<low<close，否则 break；
  抓取后统一过滤 o/c/h/l 为 0 或 h<l 的脏 bar（`kline drop bad bar`）。
- 验证：日志 `kline ok: 180 bars ... last O9.070 H9.100 L9.000 C9.100`
  （601398）、`O43.360 H43.450 L42.920 C43.320`（600036），与真实行情一致。

### 12.1 拼音键盘"字母是错的"根因
- `ui_theme.c` 里按键的 user_data 指向 `kp_char()` 的**共享静态池** `s_kp_chars[96][2]`，
  而 `ui_keypad_build()` / `ui_keypad_build_text()` 每次 build 都把 `s_kp_char_cnt = 0` 重写。
- 地图 App 的构建顺序是 `build_nav_modal()`（拼音 qwerty…，占槽 0..25）
  → `build_calib_modal()`（数字键盘 "1234567890" ".,-+"，槽 0..13 重写）。
  于是拼音键盘前 14 个键的 user_data 变成 1 2 3 / . , - +：点 q 出来 1，
  拼音框里显示的是数字。标签文字是建按钮时拷进 label 的，所以**看着对、打出来错**。
- 修法：**改整数键码**。`enum { KP_KEY_DEL=0x100, KP_KEY_OK, KP_KEY_SP, KP_KEY_CN }`，
  普通字符直接传 `(int)(unsigned char)ch`（1..0x7F）。`kp_btn/kp_tbtn` 签名变
  `(parent, label, code, x, y, w, h, bg)`，两个回调都按 code 分支，按钮之间零共享。
- 顺带修掉一个坑：中文模式里 `CN`/`SP` 按钮的标签会被事后改成"中"/"空格"，
  所以**不能用 label 文本当键值**（第一版这么改过，CN 键会失效变成输入汉字）。
- 底部功能键标签统一中文化：空格 / 删除 / 确定（原来 DEL / OK / SP）。

### 12.2 控制中心 WiFi 卡
- 去掉 WiFi 卡上的开关，**射频开关只留「WiFi 射频」那张卡**（cc_refresh 只同步 s_cc_rf_sw）。

  描边 0x3D4B6D、文字 0x9D7CFF。

### 13.2 SDIO 随机重启（R-30，根因）
- 报错 `assert failed: sdio_rx_get_buffer sdio_drv.c:953 (*buf)`。
- esp_hosted 流式接收每次按整批数据 `_h_malloc_align(len,64)` 申请**内部 DMA** 内存，
  失败即 assert → 重启。摄像头/PPA/编码占满 DMA 时随机触发（开交易 App 最易）。
- 试过 `RX_NONE`（包模式）→ 与本机 C5 从机固件握手不兼容，`process_init_event` 断言死循环，**不可用**。
- 最终补丁（改在 managed_components/espressif__esp_hosted）：
  1) `sdio_rx_prealloc()` 在 `memset(&double_buf,...)` 之后预分配 2×8KB；
  2) 分配失败重试 3 次，仍失败就用 512B 对齐栈缓冲把数据读掉丢弃（保持流同步）。
  ⚠️ 第一版"跳过不读"会让长度寄存器与数据错位 → Wi-Fi 全挂 + `Unrecoverable host sdio state`。
- 实测：改前 110s 崩 1~3 次；改后 130s 跑完整自测 0 崩溃。
- 另加：启动打印 reset reason + `sys/boots`、`sys/crashes`（>500 自动清零）；
  心跳加内部堆最低水位 `heap_int=..(min ..)`。
  ⚠️ 内部堆最低水位会掉到 20KB 甚至 1KB（摄像头管线），是 DMA 分配失败的土壤。
