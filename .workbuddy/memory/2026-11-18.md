# 2026-11-18 ESP32-P4C5 固件

## 本轮：电流声 / 自检等锁屏 / 收藏 + 下载

### 1. 电音、滋啦电流声（app_audio.c 重写输出链路）
- 根因：解码任务"解一帧写一帧"，中间阻塞读 HTTP，I2S DMA 跑空。
  ES8311 从模式还在按 MCLK 出数，空转时把残留采样推给 DAC → 周期性"滋啦"。
- 改法：**64KB PSRAM 环形缓冲 + 专用喂数任务**（prio 12，4096 栈 PSRAM）。
  - 解码侧只 memcpy 进环（满则 5ms 重试，形成背压）。
  - 喂数任务每 4KB 阻塞写 `esp_codec_dev_write`，环空时补静音（干净无声）。
  - `app_audio_out_flush()` 用标志位由消费者清环（避免 rd/wr 并发错乱）。
  - `app_audio_out_format()` 格式没变直接返回（不再无谓 close/open 造成"咔"）。
  - I2S 增加 `chan_cfg.auto_clear = true`（DMA 空补 0，不重放旧数据）。
- 音量迁移版本 `vol_ver` 提到 3：老设备统一拉回 5（之前被设成 0 没声音）。

### 2. 自检与锁屏同步（ui_boot.c / ui_shell.c）
- `ui_shell_lock_ready()` 现在要求：时间不是 "--:--"、日期不是 "--/--"、
  天气城市不是"正在加载"（天气 App 被关掉时不检查天气）。
- 检查项跑完后**等锁屏信息齐了再淡出**，最多：已连网 30s / 连接中 20s / 射频关 6s。
  等的时候提示"正在同步时间与天气…"，避免解锁看到 "--:--"。
- 自检期间 WiFi 后来连上了会补记 BOOT_WIFI（不再一直显示"待连接"）。
- 锁屏年份判定 2026 → 2024（避免写死）。
- 实测：WiFi 未连（环境无 AP）时 26s 收尾；连上后 SNTP+天气约 20~25s 收尾。

### 3. 收藏修好（ui_app_music.c）
- 旧实现只认 `s_tracks[s_index]`（本地文件），网络歌 `s_count==0` 时点了没反应。
- 新增 `s_cur_name` / `s_cur_url`（play_index / net_item_cb / play_stream_now 都设置）。
- NVS 键 `music_fav2`，每行 `名字<TAB>网址`，最多 24 条；网址空 = 本地文件。
- 播放列"只看收藏"改为读收藏表，网络歌可直接点播（存了直链）。
- 收藏按钮状态跟随当前曲目（tick 里比对 s_cur_name）。

### 4. 下载到 TF 卡
- 主页新增「下载」按钮（搜索 12 / 下载 192 / 收藏 372）。
- `download_task`（12KB PSRAM 栈）：酷我 `kuwo://` 先解析直链，取流写
  `/sdcard/Music/<歌名>.mp3`，失败退回 `/sdcard/<歌名>.mp3`；写完置 `s_rescan_req`，
  tick 里重扫曲库 + toast。
- **关键坑**：FATFS 代码页必须是 GBK 才能读写中文文件名。
  - `sdkconfig`：`CONFIG_FATFS_CODEPAGE_936=y`（+ 写进 sdkconfig.defaults）。
  - 但 VFS 不做编码转换：**文件名要自己 UTF-8→GBK**，否则 FR_INVALID_NAME(EINVAL)。
  - `gbk2utf8.c` 新增 `utf8_to_gbk()`（反查 gb2312_uni 表）。
  - `scan_dir()` 反向：dirent 是 GBK，显示名先 `gbk_to_utf8()` 再 sanitize。

### 5. 构建踩坑（本机 DLP 加密驱动）
- `ldgen.py` 会 objdump 全部静态库，耗时 5~8 分钟，容易被误判"卡死"；
  真卡死时是 `riscv32-esp-elf-objdump` CPU≈0，杀掉重跑即可。
- 杀构建后会残留 `.ninja_lock`（"Access is denied"），`rm -f /d/p4c5b2/.ninja_lock`。
- 偶发 `ParseException: Unable to parse section info file ... libesp_mm.a`：
  objdump 输出为空导致，重跑 build 即过。

## 第二轮：相机卡帧 / 价格提醒 / 分辨率帧率 / PPA 抢占

### 1. 相机预览"卡在一帧"
- 现场确认：`camera format 1280x720`、帧照常 30fps 进、`pbuf` 内容非 0，
  但用户看到画面不刷新。最可能是 PPA(DMA) 写 PSRAM 后 CPU 缓存没作废。

## 第四轮：相机卡帧真因 / 重启真因 / 个股详情 + 多提醒 + 交易日

### 1. 相机&监控"卡在进 App 那一帧"——真因是监听槽计数
- `ui_shell_preview_attach()` 走"复用空槽"分支时没同步 `s_listener_cnt`（一直是 0），
  而定时器刷新循环用 `i < s_listener_cnt` 做上界 → 一次都不执行，
  界面永远停在第 attach 时设的那一帧。
- 修复：刷新循环扫满 4 个槽位；attach 里 `s_listener_cnt = max(cnt, slot+1)`。
- 验证：日志 `camera seq=2,0,2,1`、`monitor seq=0,2`（帧号在推进）。

### 2. 点多个 App 再进设置就重启——静态控件指针悬空
- 崩溃点：`ui_app_settings.c:cam_cfg_refresh()` 在"帧率"按钮还没创建时
  就用了上一轮遗留的 `s_fps_btns[]`（进过一次设置后指向已销毁对象），
  Load access fault（LVGL `lv_obj_set_local_style_prop` / `lv_obj_invalidate`）。
- 通用修复：给 8 个 App 每个都加 `reset_ui_refs()`，在 `create()` 第一行
  把所有 `static lv_obj_t *` 置 NULL / 数组 memset（脚本批量生成）。
- 验证：3 轮 × 8 个 App 反复进出 + 设置页停留 12s，无崩溃，堆稳定 120KB 左右。

### 3. 交易 App：个股详情 + 多提醒 + 交易日有效期
- 点自选卡片 → `s_detail` 个股页（现价/涨跌/今开/昨收/最高/最低/量/额 +
  已设提醒条数），页内「价格提醒（可设多条）」进提醒列表。
- 提醒模型扩展：`secid,target,dir,days,created,dec`（NVS `sys/stk_alert`，最多 16 条，
  兼容老的 3 字段格式）；同一股票可挂多条，点 × 删除，同价同向视为更新。
- 有效期 1 / 30 交易日；`trade_day.c` 负责交易日判定。
- ETF 3 位小数：`decimals_of()` + 代码前缀兜底（5xxxxx / 15xxxx / 16xxxx），
  列表、详情、提醒、提醒列表全部按 dec 格式化。

### 4. 交易日历（trade_day.c）
- 内置 2025/2026 年"异常日"表（48 条，只存与"周一~周五上班"不同的日子，来自国务院安排），
  断网也能算；联网后从 `api.apihubs.cn/holiday/get?year=YYYY&size=400` 更新
  （`workday`:1 上班 / 2 休息），整年 110KB 必须用 PSRAM 大缓冲，8KB 会被截断。
- 接口有限流（code 80006「请求过于频繁」，51 字节），两次请求间停 3 秒，

- 验证：`1001=0(休) 0104=1(调休上班) 1121=0(周六) 1120=1`，`+30交易日=20261230`。

### 5. 锁屏提醒时间
- `ui_shell_alert_post()` 记录 epoch 毫秒并写 NVS（`sys/alert_ms`/`alert_ti`），
