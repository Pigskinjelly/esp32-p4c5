## 4. 资源影响（实测）

| 指标 | 改前 | 改后 | 原因 |
|---|---|---|---|
| 开机 `heap_int` | 132 KB | **121 KB** | `cam_worker` 8 KB 内部栈 + `trade_nvs` 3 KB |
| `heap_spi` | 16 465 KB | 16 338 KB | 帧缓冲/画布不变，差异来自启动时序 |
| 固件体积 | 3 368 064 B | **3 508 848 B**（+137 KB） | R-06：`-fno-omit-frame-pointer` 全局生效，比预估的 30 KB 多 |
| 开机耗时 | 自检 8.1 s | 8.1 s | 无变化 |

> 内部堆少 11 KB 是可接受的代价（换掉的是两类会导致 panic 的栈问题）。但**注意**：交易 App 全开时内部堆会更紧，后续加功能前应先做 R-10 的内存/分区规划。

## 5. 复现构建

```bash
cd esp32-p4c5-ipcam
source tools/idfenv.sh          # 含 ESP_IDF_VERSION=5.5（缺它会让 WIFI_RMT_* 被删）
cd /d/p4c5b2 && ninja -j 4
python -m esptool --chip esp32p4 -p COM19 -b 921600 write_flash @flash_args
```

本机 ldgen 会偶发卡死（objdump CPU≈0）：杀掉 `riscv32-esp-elf-objdump*` 与 ninja，
`touch esp-idf/esp_system/ld/sections.ld` 后重跑（未改链接段时安全）。

## 6. 需要用户确认/配合

1. **R-04 已生效的边界**：编译期默认凭据已清空，但设备 NVS 里仍保留旧凭据，所以现网设备照常联网；只有 NVS 被擦除（出厂/换版本）才需要重新配网。
2. **R-01 复现**：建议做 20 次拔插上电统计；若再出现 `Instruction access fault`，新固件会打出 `Backtrace:`，把日志给我即可定位。
3. **R-05 验证**：需要拔掉 TF 卡拍一张照（会写 flash storage 分区）。
4. **R-10 授权**：分区重排 + coredump 需要一次全片擦除（NVS 配置会丢），是否安排窗口。
5. **R-07 口令策略**：RTSP 要不要加鉴权、口令固定还是随机。
