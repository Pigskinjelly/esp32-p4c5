### 2.2 逐条详情（P0 / P1）

#### R-01【P0·已证实】冷上电在 bootloader 阶段崩溃 → HP_WDT 复位

**证据（本轮真机，19:36 被动采集，未复位设备）**
`docs/audit-2026-11-19/serial_2026-11-19T1936.log:3-11`

```
rst:0x1 (POWERON),boot:0x30f (SPI_FAST_FLASH_BOOT)
load:0x4ffb60d0,len:0x1740  … entry 0x4ffac2ca
Guru Meditation Error: Core 0 panic'ed (Instruction access fault)
PC : 0x4fc0130e   RA : 0x4ffad3a2   SP : 0x4ffbccb0   MTVAL : 0x8082fea7
```

同一次上电的第二次启动（:56-58）：
```
rst:0x7 (HP_SYS_HP_WDT_RESET),boot:0x30f …
W (50) boot.esp32p4: CPU has been reset by WDT.
```
历史样本 `main/_m1.log:3-11`（同一天 12:27）：`PC 0x4fc01308 / RA 0x4ffad3a2`，同一位置，症状为 `Illegal instruction`。

**判定依据**：`RA=0x4ffad3a2` 落在 ROM 刚加载的 bootloader 区间（`load:0x4ffac2c0`），`PC=0x4fc0xxxx` 为 ROM 代码；此时**应用代码尚未执行**。两次样本地址几乎相同（0x4fc01308 / 0x4fc0130e）。

**影响**
- 用户可见：上电/复位后有概率"黑屏一下再自己起来"，最坏情况停在 ROM 反复重启。
- 交接文档 :83 的定性「烧录复位时旧固件残留、非固件问题」**不成立**：本次是纯 POWERON，且已进入正常 app（:115 之后一切正常）。
- 属发布门禁项：涉及"能不能稳定开机"，而当前**无 backtrace、无 coredump**（R-06），无法定位。

**复现步骤（待统计复现率）**
1. 拔掉 USB 重新上电（或按复位键）20 次，串口全程记录；
2. 统计出现 `rst:0x1` + `Instruction access fault` 的比例；
3. 对照变量：`CONFIG_SPIRAM_SPEED_200M`（改 120M）、`CONFIG_ESPTOOLPY_FLASHMODE`（QIO/DIO）、bootloader `LOG_LEVEL`。

**修复方向（按顺序，先取证再改）**
1. 先开 `CONFIG_ESP_SYSTEM_NO_BACKTRACE=n` + `CONFIG_ESP_SYSTEM_USE_FRAME_POINTER=y`（R-06），拿到 bootloader 崩溃的完整调用栈；
2. 若栈指向 PSRAM 初始化/`esp_image` 校验：把 `SPIRAM_SPEED` 降到 120 MHz 做 A/B（`sdkconfig.defaults` 单行改动，可回滚）；
3. 若栈指向 flash 读：`CONFIG_SPI_FLASH_SUPPORT_BOYA_CHIP=y`（R-16）+ 降低 flash 频率到 40 MHz 验证；
4. bootloader 自身（`bootloader/` 里无自定义代码）——本轮未见定制，故优先查配置而非代码。

**验证**：20 次冷启动 0 次异常 + 串口无 `HP_WDT_RESET`。

#### R-02【P0·高概率（机制已确认）】PSRAM 栈任务写 NVS → 断言崩溃（**定时炸弹**）

**代码路径（已逐行确认）**
1. `trade_day.c:428`
   ```c
   xTaskCreateWithCaps(trade_task, "trade_day", 10240, NULL, 2, NULL, MALLOC_CAP_SPIRAM);
   ```
   → 栈在 **PSRAM**（IDF `idf_additions.h:298-305` 明确「stack 使用指定 caps」）。
2. `trade_day.c:365-369` 抓取成功后：
   ```c
   if (any) { s_ready = true; s_net_year = year; hol_save(); }
   ```
3. `trade_day.c:198-203` `hol_save()` 内 `nvs_set_str(h,"hol",buf); nvs_commit(h);` → **SPI flash 写**。
4. IDF `components/spi_flash/cache_utils.c:127`
   ```c
   void IRAM_ATTR spi_flash_disable_interrupts_caches_and_other_cpu(void)
   { assert(esp_task_stack_is_sane_cache_disabled()); … }
   ```
   `:56-65` 该函数要求**当前 SP 在内部 DRAM**，PSRAM 栈必然不满足。
5. `sdkconfig:830` 断言等级 2（完整 assert）、`sdkconfig:1848` panic 后重启 → **Guru Meditation → 重启**。

**为什么现在还没炸**（关键证据）
`docs/audit-2026-11-19/serial_2026-11-19T1936.log:291,297`
```
W (33107) trade_day: holiday 2026: rate limited, retry later
W (38697) trade_day: holiday 2027: rate limited, retry later
```
接口一直限流 → `fetch_year()` 返回 false → `any=false` → **`hol_save()` 从未执行** → 没触发。
**一旦接口配额恢复（或换到公网/别的 IP），第一次成功抓取就会进入该路径。** 且因为崩溃发生在写入前，重启后 `hol` 仍为空 → 再次抓取 → 再次崩溃 → **重启循环**（直到 3 分钟退避把时间拉长，表现为"开机几分钟就重启一次"）。

**影响**：**极高**。属于"明天就可能全网爆发"的隐雷，且现有诊断手段（R-06）抓不到现场。

**复现步骤（真机，5 分钟可证伪）**
1. 把 `trade_day.c:368` 临时改为无条件 `hol_save();`（或直接造一个 `s_net_year=-1` 的调用）；
2. 串口应出现 `assert failed: esp_task_stack_is_sane_cache_disabled cache_utils.c:127` + `Guru Meditation`；
3. 验证完立刻回滚。

**修复方案（两种，均小改可回滚）**
- 方案 A（推荐，最省事）：`hol_save()` 不直接写，改为置 `s_hol_dirty=true`；在 `main.c` 的 `storage_task`（内部栈、4096 足够）启动里加一次「开机补写」，并在 `trade_task` 里改用一个**内部栈小任务**（`xTaskCreate(..., 2048)`）承接写入。
- 方案 B（一行改）：`xTaskCreateWithCaps(..., MALLOC_CAP_INTERNAL)`，但 TLS 握手吃栈，10240 内部栈在 heap_int 只剩 66 KB 时可能创建失败 → 需降 `hol` 缓冲或改用 8192。**风险高于 A**。

**验证**：修复后强制触发一次成功抓取，串口出现 `calendar ready` 且无 assert，`trade/hol` 在重启后仍存在（`holiday cache loaded`）。

> **同类隐患扫描（本轮全量 grep）**：其余 PSRAM 栈任务（music 32768 / map 16384 / kline 14336 / download 12288 / wx 8192 / cam_worker 8192）均**未**在任务内直接写 NVS（NVS 写都在 LVGL 回调=内部栈），故 R-02 目前只有 `trade_day` 一处；但 `R-05` 属同一机制的第二个入口。

#### R-03【P0·已证实】构建不可复现、不可回滚

#### R-07【P1·已证实】RTSP 无鉴权 / 无上限 / 可被低成本打挂

**证据**
- `rtsp_server.c:626` `.sin_addr.s_addr = htonl(INADDR_ANY)` — 对全网卡监听，无 IP 白名单；

1. 加 `#define RTSP_MAX_CLIENTS 4`，超限 `accept` 后立即 `close`；
2. 加 Basic 鉴权（`OPTIONS/DESCRIBE` 要求 `Authorization`，口令存 NVS 随机生成，屏幕控制中心显示）；
3. `malloc(len)` 改 `len > 2048 → 直接丢弃`（RTCP 报文不可能这么大）。

**验证**：`ffplay` 无口令被 401 拒；`for i in $(seq 10); do ffplay … & done` 时心跳 `rtsp_clients≤4`、heap_int 不跌。
