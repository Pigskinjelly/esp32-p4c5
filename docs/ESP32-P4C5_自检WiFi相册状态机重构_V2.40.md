## 一、系统自检（`ui_boot.c` 重写）

### 设计稿结构

```
开机自检                        5/5
● 相机 SC2336            I2C-0 · 296W
● TF 卡                  1.2GB / 3.4GB
● WiFi 模块              <WiFi名称> · -30dBm
● RTSP 服务              0.0.0.0:554
● 内存                   内部 12M / 1.8M
▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬
自检完成，正在进入桌面
ESP32-P4C5 · 开机自检                    [跳过]
```

### 状态机

| 状态 | 触发条件 | 界面 |
|---|---|---|
| `BS_CHECKING` | 进入自检 | 状态条青色，提示「正在自检 n/5 …」 |
| `BS_ALL_PASS` | 5 项全部为通过 | 状态条绿，提示「自检完成，正在进入桌面」 |
| `BS_PARTIAL_FAIL` | 各项结束但有失败 | 状态条红，提示「N 项未通过，请在设置里检查」 |
| `BS_TIMEOUT` | 8 秒仍未结束 | 状态条橙，提示「自检超时（n/5），先进系统」 |
| `BS_CANCELLED` | 点「跳过」 | 状态条灰蓝，提示「已跳过自检」 |

单项状态：`-1 未完成（灰空心）` / `1 通过（绿实心）` / `0 失败（红实心）` / `-2 跳过（灰）`。

### 与旧实现的差异

| 项 | 旧 | 新 |
|---|---|---|
| 检查项 | 7 项（系统/显示/触摸/内存/网络/相机/存储），2 列文字 | 5 项（相机/TF 卡/WiFi/RTSP/内存），单列「圆点+名称+右侧实测值」 |
| 进度 | 无 | 右上角 `n/5` |
| 结果展示 | 一行 hint | 整宽状态条（颜色随阶段变）+ 文案 |
| 用户干预 | 只能等（8s 超时） | 可点「跳过」→ `BS_CANCELLED` |
| 显示/触摸 | 独立两项 | 并入「相机」项文案（`480x480 · 触摸 OK`），信息不丢 |

### 接口保持

`ui_boot_check_begin/mark/skip/done` 四个函数签名不变，`main.c` 的调用点只调整了枚举名。
枚举由 7 项改为上图 5 项：

```c
enum { BOOT_CAM, BOOT_STORE, BOOT_WIFI, BOOT_RTSP, BOOT_MEM, BOOT_ITEM_CNT };
```

`main.c` 相应改动：
- 新增 `BOOT_RTSP` 上报（`rtsp_server_start` 结果 → `0.0.0.0:554` / `启动失败`）；
- 删除 `BOOT_DISP/BOOT_TOUCH/BOOT_SYS` 上报，触摸状态存进 `s_touch_ok`，拼进相机项文案；
- 相机失败文案对齐设计稿：「I2C 无响应」「打开失败 · 无画面」。

## 二、WiFi（`ui_shell.c` + `wifi_mgr.c`）

### 设计稿结构

单页「附近网络」：标题 + 关闭、列表（SSID + 信号 + 锁 + 连接/已保存）、底部「重新扫描」。
派生状态：扫描中（圆环 + 占位）、空列表、密码框（连接中/密码错/超时/拒绝）。

### 状态机

`wifi_ui_stage()` 是唯一判定入口，所有 UI 可见性由它驱动：

| 状态 | 判定 | 界面 |
|---|---|---|
| `WUS_OFF` | `!wifi_mgr_is_on()` | 控制中心显示「WiFi 已关闭」 |
| `WUS_SCANNING` | `state == SCANNING` | 列表隐藏，显示圆环 + 「正在扫描附近网络…」+ 3 条占位 |
| `WUS_LIST` | 其它且扫描结果非空 | 列表 |
| `WUS_EMPTY` | 扫描结束结果为 0 | 「未找到网络，换个位置或点「重新扫描」」 |
| `WUS_CONNECTING` | `state == CONNECTING` | 密码框内「正在连接…」 |
| `WUS_CONNECTED` | `state == CONNECTED` | 密码框自动关闭 + toast「已连接」 |
| `WUS_AUTH_FAIL` | `wifi_mgr_auth_failed()` | 框内红字「密码错误，请重新输入」 |

### 密码框的流转（对齐设计稿 15/22/23/24）

```
点列表项 ──有密码──> 直接连
        └─无密码──> 弹框
                     ├─ 点「连接」→ 显示「正在连接…」，框不关
                     ├─ 连上     → 自动关框
                     ├─ 密码错   → 红字，留在框里重输
                     ├─ 找不到AP → 「找不到该网络，请靠近路由器」
                     ├─ 拒绝接入 → 「路由器拒绝接入」
                     └─ 12s 无果 → 「连接超时，请重试」
```

为此新增 `wifi_mgr_last_reason()`（返回 `wifi_err_reason_t`），
用 `WIFI_REASON_NO_AP_FOUND / ASSOC_FAIL / CONNECTION_FAIL / AUTH_FAIL` 区分文案。

### 其它对齐点

- 标题「附近的 WiFi」→「附近网络」；
- 扫描中列表不再显示旧结果（避免"扫完了还转圈/转圈时还有旧列表"）；
- 「重新扫描」按钮由 180×42 圆角改整宽 408×44 胶囊，贴面板底部；
- 空态文案改为「未找到网络…」。

### 状态驱动刷新

`shell_timer_cb`（30ms）里比较 `s_wifi_stage_last`，状态一变就 `ap_list_rebuild()`，
不再依赖某个事件恰好设置了 `s_ap_list_dirty`。

## 三、相册（`ui_app_gallery.c`）

设计稿是 2 列网格 + 底部 `‹ 1/5 ›` 分页 + 每格底部日期。现有实现已经是
`GRID_COLS=2` + 分页 + viewer，本轮只补差异：

- 网格底部文案由**文件名**改为**拍摄日期** `MM-DD HH:MM`
  （`photo_caption()` 用 `stat().st_mtime`；FATFS 无有效时间时退回文件名）；
- 空态文案本就与设计稿一致（「暂无照片，去相机拍一张吧」），未改。

相机 App（`ui_app_camera.c`）已有 `s_capture_state`（idle/busy/ok/fail）+ `s_err`，
覆盖设计稿「拍摄中 / 无相机权限 / 预览」三类，本轮不动。
